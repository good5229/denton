# Phase241 건설업 시군구 WAPE 개선용 공개자료 탐색

생성일: 2026-07-29

## 결론

건설업 시군구 WAPE 10% 목표를 위해 먼저 확보해야 할 자료는 성능 실험보다 `부문별 event 원자료`다.

우선순위는 다음과 같다.

1. **서울시 도시정비사업 통계**: 강남구·영등포구·강서구 같은 서울권 고오차 지역의 재건축·재개발 블록.
2. **건설CALS 연도별 공사계약 목록**: 공사명·도급액·계약일·착공일·준공일을 포함하는 공공/토목 공사 블록.
3. **조달청 나라장터 계약정보·발주계획·입찰공고**: 공공공사 소재지·계약금액·발주시점 보조.
4. **LH 분양임대공고/공고문**: 공공주택·택지·임대주택 대형사업 보조.
5. **지역별 공동주택 사업승인·착공현황 파일**: 전국 표준성은 낮지만 특정 시군구 보강자료.

현재 BuildingHUB는 top5까지 수집했지만 단독 보정 route는 미채택이다. 따라서 다음 수집은 BuildingHUB 확장이 아니라 정비사업·공공/SOC·공사계약 자료가 우선이다.

## 3. 실험 연결 방식

### 3.1 서울권: 강남구·영등포구·강서구

필요 블록:

- 서울 도시정비사업 통계
- BuildingHUB 허가·착공·사용승인
- 조달청 계약/입찰

사용 방식:

- 정비사업 단계별 event score 생성
  - 구역지정/조합설립: 약한 선행신호
  - 사업시행인가/관리처분: 중간 선행신호
  - 착공/준공: 강한 건설활동 신호
- BuildingHUB는 정비사업과 충돌하면 단독 사용하지 않음.
- 서울권은 대형 정비사업/상업건축/본사소재지 영향이 크므로 `정비사업 블록 우선`이다.

### 3.2 평택·여수형: 산업·항만·SOC 혼합

필요 블록:

- 건설CALS 연도별 공사계약
- 조달청 계약정보/발주계획/입찰공고
- 항만·도로·산단 사업정보

사용 방식:

- 공사계약 도급액과 착공·준공일로 분산지표 생성.
- PPS는 공공공사 보조 신호로만 사용.
- BuildingHUB는 민간건축 블록으로 제한.

## 5. 다음 실행 순서

1. 서울 도시정비사업 통계 XLSX 다운로드 및 파싱.
2. `CALS_API_KEY` 확보 후 연도별 공사계약 목록 probe.
3. 조달청 계약정보/발주계획 API 승인 여부 확인.
4. top5 지역에 대해 `정비사업 + CALS/PPS + BuildingHUB` feature table 생성.
5. Phase240과 동일한 guardrail로 재검증.

## 6. 현재 결론

건설업 성능개선의 다음 병목은 모델식이 아니라 자료다.

- BuildingHUB 단독: 실패.
- BuildingHUB small-shift: 실패.
- 필요한 다음 자료: 서울 정비사업, CALS 공사계약, 조달청 계약/발주계획, LH 공공주택 공고.

이 자료가 들어오기 전에는 시군구×건설업 WAPE 10% 이하를 주장하기 어렵다.
