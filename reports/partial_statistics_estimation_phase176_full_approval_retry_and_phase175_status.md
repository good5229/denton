# Phase176 추가 활용신청 이후 API 재점검 및 운영형 결합실험 상태

## 목적

사용자가 조달청·금융공공데이터·기타 직접 활동자료 후보에 대해 추가 활용신청을 완료했다고 알려준 뒤, 실제 API 호출 가능 여부를 다시 확인했다. 동시에 이미 로컬에서 사용 가능한 자료만으로 Phase175 운영형 결합실험을 실행해 고양시·포항시 중분류 GVA 추정 성능 변화를 점검했다.

## 1. 추가 승인 API 재점검

### 점검 결과

| 구분 | 점검 자료 수 | 사용 가능 행 | 상태 |
| --- | ---: | ---: | --- |
| Phase166 조달청 사용자정보·업종근거법규 계열 | 5 | 0 | 전부 `Forbidden` |
| Phase167 보건·폐기물·물류·건강보험 계열 | 8 | 0 | 7건 `Forbidden`, 1건 인증키 오류 |

### 판정

현재 실행 기준으로는 추가 승인 완료 후에도 API 응답이 열리지 않았다. 따라서 이 자료들은 아직 GVA 추정모형에 반영하지 않았다.

가능성이 높은 원인은 다음 세 가지다.

1. 활용신청 승인 반영 지연
2. 현재 `.env`의 공공데이터포털 키와 신청 서비스 연결 불일치
3. 일부 API의 별도 게이트웨이·별도 인증키 요구

특히 ODCloud 건강보험 계열은 공공데이터포털 일반 `serviceKey`와 다른 인증 방식일 수 있어 별도 확인이 필요하다.

## 2. Phase175 운영형 결합실험

### 적용 원칙

Phase175는 타깃 중분류 actual을 적용 판단에 사용하지 않고, 다음 두 규칙만 결합했다.

1. H00 운수·창고업은 Phase164 peer-distance 경로를 사용하지 않고, Phase173 항만물동량 게이트만 사용
2. H00 외 상위산업은 Phase164에서 타깃 actual 없이 통과한 peer-distance 게이트만 사용

타깃 actual은 성능 사후감사에만 사용했다.

## 3. 해석

Phase175는 전체 WAPE를 18.86%에서 17.06%로 낮췄고, 포항시의 20% 초과 셀도 30개에서 26개로 줄였다. 특히 포항 운수·창고업은 항만물동량이 있는 도시에서만 수상운송업 보강을 허용했기 때문에 고양시에 잘못 적용되는 문제를 피했다.

다만 포항 금융업과 방송업은 peer-distance 경로 적용 후 악화가 남아 있다. 따라서 Phase175는 “완성된 최종 성능”이라기보다 **운영 후보 + 악화감사 포함 모형**으로 보아야 한다.

## 4. 다음 작업

1. 추가 승인 API가 실제로 열리는지 일정 시간 뒤 재시도한다.
2. 조달청 사용자정보가 열리면 MN0/F00/사업지원/전문서비스 쪽 직접 활동자료로 편입한다.
3. 금융공공데이터가 열리면 K00 금융·보험업의 peer-distance 의존도를 낮춘다.
4. KOBIS는 사용 가능, KOPIS는 사용 불가이므로 J00 영상·콘텐츠 계열은 KOBIS 중심으로 제한 적용한다.
5. 포항 방송업처럼 소규모·불안정 셀은 단일 보정 대신 상위산업 내 합산 안정화, 최소규모 필터, 전년 추세 완충을 적용하는 별도 후보를 검토한다.
